# Mây Live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task (execution method already chosen). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move Mây's weekly call to a Gemini Live real-time voice session, modelled on the "gọi Nếp" call in topik-app, so Mây listens, answers what was just said, digs as long as the story needs, and gets as many rich, real stories as possible out of parents and children.

**Architecture:** The server hands out a one-use Live token with Mây's brief, voice, tools, VAD and context sliding locked inside (`server/calllive.ts`, like `topik-app/server.js:1171-1194`); the browser talks to Google directly (`src/CallLive.tsx`, `src/livePlayer.ts`, `public/mic-worklet.js`). The brief is rebuilt each call from the existing data (`context()` + `loadScriptExtras()`) plus a depth level, ranked seeds and weather as a feeling (`server/callfacts.ts`, `server/place.ts`). The model drives the call and reports structure through tools; a pure client module (`src/liveTurns.ts`) turns tool calls and Live events into the same rows the old call wrote (`call_answers` per turn with the teller's own voice, story slots in a `v: 3` script, share consent, relays), so podcast, memory, signals and calendar keep working unchanged after `/finish`.

**Tech Stack:** React 19 + Vite (`app/src`), Express 5 + Postgres via `pg` (`app/server`), run with `tsx`, tests with `node:test`, Gemini Live over WebSocket (`BidiGenerateContentConstrained`) with ephemeral tokens (`POST /v1beta/auth_tokens`), AudioWorklet mic at 16 kHz, Web Audio playback at 24 kHz, MediaRecorder per turn.

**Spec:** `app/docs/may-that-hon-dieu-tra.md` (21/11/2026). Section G is the target architecture, section F covers depth and seeds, "Mục tiêu" is the goal every choice is scored against. Sections A to E explain today's problems with file:line evidence. Read G, F and "Mục tiêu" in full before your task. ## Rulings (made by the user and the coordinating agent; binding)

1. **Rollout behind a per-member beta switch, no Railway env changes needed.** `members.may_live boolean not null default false`; a small switch "Thử Mây mới" in Settings sets it; a member with `may_live = true` gets `CallLive`, everyone else keeps today's `Call.tsx` unchanged. Server env `MAY_LIVE=off` (also `0`) disables Live entirely (kill switch, default on). `GEMINI_LIVE_MODEL` defaults to topik-app's model: `gemini-3.8-live` (sent as `models/gemini-3.8-live`, `topik-app/server.js:879`).
2. **Spend control.** App-wide daily minute cap `MAY_LIVE_DAILY_MIN` (default 120), per-call cap `MAY_CALL_MAX_SEC` (default 900), token usage and a USD estimate logged per call (Nếp's usage math). Cap reached or token request failed: fall back to the old call screen with a short line.
3. **Privacy.** `intro.unsaid` never goes into the Live prompt. Facts with visibility `self` told by others are never included. The listener's own private facts are allowed only in the check-in, never as or inside a story opener. Story openers saved via `story_open` pass `suspect()` and a private-fact check before they are stored, because they become question cards in shared episodes.
4. **Consent** only comes from the two buttons or the `callShare.ts` parser on the transcript, never from the model's own judgement. One consent per call covers all stories in it (accepted for v1).
5. **The first task is a spike:** server token endpoint and a bare client page that connects, speaks Vietnamese with Zephyr, records one turn and shows latency, testable on the user's phone through the beta switch. If Zephyr sounds bad in Vietnamese, nothing later may depend on the voice name: it stays env-configurable.
6. **No real network in tests.** Mock the token endpoint and the WebSocket at the boundary. Tools and their effects (`story_open`, `story_close`, `ask_photo`, `ask_share`, `relay_heard`, `relay_open`, `end_call` with `next_hook`) are tested as plain functions.

Rulings added by this plan (reasons in "Decisions" at the end): 7. the Live voice env is `MAY_LIVE_VOICE`, falling back to `GEMINI_VOICE`, then `Zephyr`; 8. the server enforces the beta switch; 9. Mây's per-turn question stored on a story answer passes the same checks as an opener; 10. story slots are written in order by outbox `last` jobs and `/answer` never needs the slot; 11. Mây's audio is held back while the share answer is being decided.

## Review Focus

1. **Outbox reorders jobs.** `src/outbox.ts` runs every job of a group in parallel except `last` jobs, so an answer for story 3 can reach the server before story 3's slot, or story 3's slot before story 2's. The answer must still be stored with the right topic, and the slot list must never have a hole. Pinned in Task 4 (`liveAnswerRow` without a slot, `placeStory` padding) and Task 5 (`/story` jobs are `last`).
2. **The model calls a tool badly**: a theme not allowed for the role, an empty opener, `relay_heard` with an id that is not pending or already heard, `ask_share` twice or before any story or in a one-person family, `end_call` with an empty hook, an unknown tool. No crash, a short result text that lets the model carry on, no job queued. Pinned in Task 5 (`onTool` tests).
3. **Hanging up or losing the socket mid-turn**: the turn being recorded, or closed but waiting for its transcript, is uploaded exactly once; a turn with no voice is not uploaded; nothing said during the share question is uploaded as a story turn; `live-end` is sent once with the right seconds even when the socket never opened. Pinned in Task 5 (`captureNext` hangup tests) and Task 1 (`live-end` clamp test).
4. **Daily cap edges**: a call whose page never reported back counts as a full `MAY_CALL_MAX_SEC`; under 60 s left refuses with `live_cap`; the token's `expireTime` follows the smaller of the per-call cap and what is left today; a page cannot report more seconds than the token allowed or report twice. Pinned in Task 1.
5. **Private text leaking into shared artifacts**: an opener, a per-turn question card or a `next_hook` that carries a bigram of the listener's own private fact or of `intro.unsaid`, or an unknown name, is never stored as is. Pinned in Task 4 (`cardText`, `saveStory`, `finishLive` tests).

`onTool` results (English, final) and effects:
- `story_open`: theme not in `s.themes` or empty opener: result `Not opened: use a theme from DATA.allowed_themes and say the opener.`, no effect. Otherwise idx = `s.next`, next + 1, theme and opener stored (opener max 300), effect job `{ url: /api/call/<id>/story, fields: { idx, theme, opener }, last: true }`, result `Story opened.`
- `story_close`: idx back to 0, theme null; result `Story closed. Open the next seed or go to the closing steps.`
- `ask_photo`: idx < `LIVE_FIRST_STORY`: result `No story is open: skip the photo.`; else effect photo, result `The photo button is showing. Wait for them; the app will tell you how many photos arrived.`
- `ask_share`: family < 2: `They are the only one in the family: skip this step.`; `storyTurns === 0`: `No story was told: skip this step.`; share not `none`: `Already asked: do not ask again.`; else share `asking`, effect share, result `The two buttons are showing. Ask your one short question now, then say nothing until the app tells you the answer.`
- `relay_heard`: id not in `relays` or already in `heard`: `Unknown message id.`; else add to heard, effect job `{ url: /api/call/<id>/relay/<encodeURIComponent(rid)>/heard, fields: {} }`, result `Delivered.`
- `relay_open`: family < 2: `They are the only one in the family: skip this step.`; else idx 1, result `Ask now.`
- `end_call`: hook = trimmed `next_hook` (max 200), effect end, result `Say nothing more; the app hangs up.`
- any other name: `ok`, no effect.

`onTurn`: share `asking` gives no job (the answer is for the consent step, not a story turn); `seconds < 1` and empty transcript gives no job. Otherwise job `{ url: /api/call/<id>/answer, fields: { live: '1', idx, turn: String(s.turns[idx] ?? 0), question (max 300), transcript, seconds, ...(idx >= LIVE_FIRST_STORY ? { theme, opener } : {}) } }`, bump `turns[idx]`, bump `storyTurns` when idx is a story. The caller attaches the recording blob.

`onShareEnd`: share `done`; `yes`: job `{ url: /api/call/<id>/share, fields: {} }`, cue `CUE.shareYes`; `no` and `timeout`: job `{ url: /api/call/<id>/keep, fields: {} }`, cue `CUE.shareNo`; `hangup`: no job, no cue. idx back to 0 in every case.

`captureNext` (the per-turn recording; `key` counts turns):
- `gate` (Mây has been quiet for `MIC_GATE_MS` plus output latency): not recording: key + 1, recording, `heard = ''`, `loud = false`, action `startRec`.
- `loud`: `loud = true`.
- `in`: appended to `pending.heard` when a turn is closed but not yet sent, else to `heard` (the mic is muted while Mây talks, so late transcripts belong to the closed turn).
- `out`: appended to `mayLine`.
- `audio` (first model audio of a turn): recording: action `stopRec` with the key, `pending = { key, question, heard, loud }`, not recording.
- `done` (model `turnComplete`): pending with `loud` or non-empty `heard`: action `turn`; pending cleared either way; `mayLine` trimmed non-empty: action `mayLine`, it becomes `question`, `mayLine` cleared.
- `hangup`: recording: `stopRec` then `turn` when voiced; pending: `turn` when voiced; a second `hangup` emits nothing.

## Decisions this plan makes where the spec left room

- **Ruling 7, voice env:** `GEMINI_VOICE` already picks the old call's Gemini TTS voice and is part of its cache key (`server/voice.ts:19`); changing it to try another Live voice would re-read every cached line and burn the 70-a-day budget. Live reads `MAY_LIVE_VOICE`, then `GEMINI_VOICE`, then `Zephyr`, so it stays env-configurable without touching the old call.
- **Ruling 8, server-side beta check:** `/call/live` refuses members with `may_live = false` (403). A client flag alone does not control spend.
- **Ruling 9, per-turn cards:** podcast cards show each answer's `question` (`server/podcast.ts` `piece.question`), which for Live is Mây's live line, not only the opener. It gets the same `suspect()` plus private-fact check; on failure the opener (checked too) or the topic name is stored.
- **Ruling 10, slot order:** the outbox sends a group's jobs in parallel except `last` ones, so `/story` jobs are `last` (they land in order, after the answers queued before them), `/answer` with `live=1` never needs the slot (topic from slot or theme), and `placeStory` fills any hole.
- **Ruling 11, consent audio:** Live answers the user's "dạ được" by itself before the app can decide, so Mây's audio is dropped from the share question until the app sends the decision cue.
- Story slots: v3 scripts always have slot 0 (check-in, `hoi-tham`) and slot 1 (hard-to-say message, `loi-nhan`, unused in one-person families), stories from `LIVE_FIRST_STORY = 2`. Turns after `story_close` go to slot 0, keeping episodes free of chit-chat; turns during the share question are not uploaded (same as the old call).
- `turnOf` caps the old call at 4 turns and `limitAnswer` allows 30 answers per 10 minutes; Live answers use `LIVE_MAX_TURNS = 200` and their own limiter (120 per 10 minutes), since a 15-minute call has no fixed number of follow-ups.
- `/story` and `/finish` get `upload.none()`: outbox jobs with fields are sent as multipart.
- Live usage lives in four new `calls` columns (`live_at`, `live_sec`, `live_usd`, `live_usage`); the daily cap is computed from them, and a call that never reported counts as a full call.
- Live DATA leaves out own earlier transcripts (`c.stories`): they include check-in answers with no privacy flag. Memory facts carry the same knowledge with flags.
- `intro.love = never` reaches the model only as `warm_tone: true`, never as the answer itself.
- Model-facing cues and the brief are English like every other prompt (i18n rule); Vietnamese examples sit in `i18n-ok` blocks.
- The client imports the haystack-free `slip()` from `server/guard.ts` (first client import from `server/`; the module is pure and its only import is type-only), rather than copying its regexes.
- Token request happens after the user picks up, not during the ring, so a declined ring never reserves daily minutes.
